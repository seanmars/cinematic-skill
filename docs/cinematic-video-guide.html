render(t)

畫面只由時間決定

Claude 沒辦法直接輸出影片.它改寫一個網頁,網頁提供 render(t): 給它一個秒數,它就畫出那一格.渲染腳本從第 0 秒開始逐格呼叫,截圖後交給 FFmpeg 編碼.

藍圖brief.md每顆鏡頭的內容與時間
畫面程式index.htmlwindow.render(t)
逐格截圖render.pyt = 0, 1/30, 2/30 ...
編碼out/final.mp4FFmpeg + 混音
t = 1.60s第 48 格
0s.511.522.533.544.555.5

拖動滑桿就是在改變 t.底片條上的 12 格是在不同秒數各自畫出來的,不管用什麼順序重畫,結果都一模一樣.為了看得清楚,這裡的動態模糊把快門時間放大了.

改一顆鏡頭,只重渲那幾秒

任何一格都能單獨重畫,所以修正第 8 秒的問題時,不用整支片重來.

沒有藏起來的狀態

隨機數一律固定種子,不用計時器,也不把上一格的結果留給下一格.skill 會用 seek test 驗證這一點.

動態模糊是算出來的

把一格切成幾個子幀再平均.4 個子幀代表渲染時間變成 4 倍,Claude 會先告訴你.

gauntlet

faq

常見情境

我想要真人或寫實的角色

程式碼畫不出寫實人物.可以先用影片模型 (例如 Grok,Kling,Seedance) 生成純綠幕背景的人物片段,skill 會去背,再疊進用程式做的場景,大字和動效裡.

渲染太慢怎麼辦?

先用較低的解析度或幀率出小樣,確認後再出正式版.動態模糊和 WebGL 後製最耗時.修改時只重渲有問題的那幾秒.

我只想要提示詞,不需要影片

直接說 "只要 brief.md".這份檔案就是完整的結構化提示詞,可以換主題重用,也可以拿到其他工具裡跑.

確認方案之後還能改嗎?

可以.指出時間點和問題,Claude 只會修正那顆鏡頭,重渲那幾秒,再重新審片.
